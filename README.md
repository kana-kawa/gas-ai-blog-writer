# ブログ記事 下書き自動生成ツール

Google スプレッドシートにキーワードを入れてメニューを押すと、OpenAI で記事本文とメタディスクリプションを生成し、スプレッドシートに書き出します。WordPress へ送る内容（ペイロード）は実行ログに出します。live モードにすると、WordPress に**下書き**として保存します。

> このリポジトリのデモでは、実投稿はせず、スプレッドシートへの書き出しとペイロードのログ確認までを行っています（`MODE=ai_only`）。

- AI の下書きは 60〜70 点が目安です。人が 10 分ほど編集して 90 点に仕上げてから公開してください。
- 本文中の【要確認】は、法律の数字や統計など、公開前に事実確認が必要な箇所の印です。
- 画像の設定と公開は手作業です（自動では公開しません）。

---

## 使用技術

| 技術 | 用途 |
|---|---|
| Google Apps Script（JavaScript / V8） | ツールの実行環境。スプレッドシートのカスタムメニューから動かす |
| Google スプレッドシート | キーワード入力、ステータス管理（入力規則のプルダウン）、生成結果の書き出し |
| OpenAI Responses API | 記事の生成。構造化出力（JSON スキーマ）で `{title, body_html, meta_description}` を受け取る |
| WordPress REST API | 下書きの作成（`status: 'draft'`）。認証はアプリケーションパスワード |
| スクリプトプロパティ | API キー・パスワードの保存（コードにハードコードしない） |
| clasp | ローカルで開発し、Apps Script に反映 |
| Node.js | 文法チェックと、GAS の API をまねた環境での動作テスト |

### 設計で工夫したこと

- **GAS の 6 分制限への対策**：4 分半を過ぎたら残りの行を残して自分で止まり、次の実行で続きから生成する
- **二重実行の防止**：`LockService` で同時実行を防ぎ、同じ記事を二重に作らない
- **通信エラーへの対応**：AI への依頼は混雑時（429・5xx）に 1 回だけやり直す。WordPress への送信は、下書きの重複を防ぐためやり直さない
- **送信内容の確認**：WordPress へのペイロードを「作成」と「送信」に分け、送らないモードでも `Logger.log` で中身を確認できる
- **3 つのモード**：`mock`（API なし）／`ai_only`（AI だけ）／`live`（WordPress まで）を、設定だけで切り替えられる
- **安全側の設計**：自動で公開せず必ず下書きで止める。パスワードを送るのは `https://` のサイトだけ
- **プロンプトの 4 ブロック構成**：役割定義・見本記事・構成テンプレート・制約条件に分け、直したい部分だけを書き換えられる。生成した記事を検証して制約条件を改善した（「4. 生成した記事のチェック記録」を参照）

## 1. 操作マニュアル（毎回の使い方）

1. シートの A 列にキーワード、B 列にサブキーワードを入れ、C 列（ステータス）を「未生成」にします。
2. メニュー「記事生成」から、次のどちらかを選びます。
   - **選択した行の記事を生成**：選んだ行だけを生成します。
   - **未生成の記事をまとめて生成**：ステータスが「未生成」「エラー」の行をすべて生成します。
3. ステータスが「生成中」→「生成済み」に変わります。D 列にタイトル、H 列に本文（HTML）、I 列にメタディスクリプションが入ります。
   - live モードのときは「下書き保存」になり、E 列に WordPress の編集画面の URL が入ります。E 列の URL を開いて編集し、画像を設定して公開します。公開したら C 列を「公開済み」にしてください。
4. WordPress に送る内容を確かめるときは、Apps Script エディタの左の「実行数」を開き、実行した処理を選びます。`[WordPress 送信ペイロード]` の行に、`title` / `content` / `status: 'draft'` / `excerpt` が出ています。

| こんなとき | どうする |
|---|---|
| ステータスが「エラー」になった | G 列の理由を確認し、直してからもう一度実行します（エラーの行は再実行の対象です）。 |
| 「時間切れのため○件が残っています」と出た | もう一度同じメニューを実行すると続きから生成します（1 回の実行は 6 分までという GAS の制限のため）。 |
| 生成し直したい | C 列を「未生成」に戻してから実行します。live モードでは WordPress に新しい下書きが追加されるので、古い下書きは手で削除してください。 |
| 文体や構成を変えたい | `src/Prompt.js` の 4 つのブロック（役割定義・サンプル記事・構成テンプレート・制約条件）を直します。 |

### シートの列

| 列 | 内容 |
|---|---|
| A キーワード / B サブキーワード | 入力する |
| C ステータス | 未生成 → 生成中 → 生成済み（live モードは下書き保存）／ エラー ／ 公開済み |
| D タイトル | 生成結果 |
| E WordPress URL | live モードのときだけ入る |
| F 生成日時 / G メモ・エラー内容 | 記録（G には本文とメタディスクリプションの文字数も入る） |
| H 本文（HTML） / I メタディスクリプション | 生成結果 |

## 2. 設定（スクリプトプロパティ）

Apps Script エディタの「プロジェクトの設定（歯車）→ スクリプト プロパティ」で登録します。API キーはコードに書きません。

| プロパティ | 内容 | 必要なモード |
|---|---|---|
| `MODE` | `mock`（AI も WordPress も呼ばない）／ `ai_only`（AI だけ。デモはこれ）／ `live`（WordPress まで通す）。未設定なら `mock` | — |
| `OPENAI_API_KEY` | OpenAI の API キー | ai_only, live |
| `OPENAI_MODEL` | 使うモデル。未設定なら `gpt-6.1-sol` | 任意 |
| `OPENAI_REASONING_EFFORT` | 推論の深さ（`low` など）。生成が遅いときに試す。未設定なら送らない | 任意 |
| `WP_BASE_URL` | WordPress のサイト URL（例：`https://example.com`。末尾の `/` は不要） | live |
| `WP_USER` | WordPress のユーザー名 | live |
| `WP_APP_PASSWORD` | WordPress のアプリケーションパスワード | live |

メニュー「現在の設定を確認」で、足りない設定がないか確認できます（キーの中身は表示しません）。

WordPress のアプリケーションパスワードは、管理画面の「ユーザー → プロフィール → アプリケーションパスワード」で発行します。下書きを作れる権限（投稿者以上）のユーザーで十分です。

## 3. 開発者向けセットアップ（clasp）

```
npm install -g @google/clasp   # 済みなら不要
clasp login                     # ブラウザで Google にログイン
```

1. https://script.google.com/home/usersettings で「Google Apps Script API」をオンにします。
2. このフォルダで `clasp create-script --type sheets --title "ブログ記事 下書き自動生成" --rootDir src` を実行します。スプレッドシートと Apps Script が作られ、`.clasp.json` ができます。
3. `clasp push` でコードを Apps Script に反映します（GitHub への push とは別物です）。
4. `clasp open-container` でスプレッドシートを開き、再読み込みするとメニュー「記事生成」が出ます。
5. `src/SampleArticle.js.example` をコピーして `src/SampleArticle.js` を作り、見本記事の本文を貼り付けます（クライアントから受け取った見本記事のため、このファイルは GitHub には上げていません）。もう一度 `clasp push` します。
6. 「ファイル → インポート → アップロード」で `keywords.csv` を読み込み、メニュー「シートを初期設定」を実行します。初回は権限の承認画面が出ます。

列を追加したバージョンに更新したときも、「シートを初期設定」をもう一度実行してください（見出しとプルダウンが新しくなります。データは消えません）。

### ファイル構成

| ファイル | 役割 |
|---|---|
| `src/Menu.js` | カスタムメニュー |
| `src/Main.js` | 生成処理の全体（対象行の選択、6 分対策、同時実行の防止） |
| `src/Sheet.js` | 列の定義、ステータスの読み書き、初期設定 |
| `src/Config.js` | スクリプトプロパティの読み込みとチェック |
| `src/Prompt.js` | プロンプト（役割定義・サンプル記事・構成テンプレート・制約条件） |
| `src/SampleArticle.js` | プロンプトに入れる見本記事（GitHub には上げていない。見本は `src/SampleArticle.js.example`） |
| `src/OpenAI.js` | OpenAI Responses API の呼び出し（JSON スキーマで `{title, body_html, meta_description}` を受け取る） |
| `src/WordPress.js` | 送信ペイロード（`title` / `content` / `status: 'draft'` / `excerpt`）の作成とログ出力、WordPress REST API での下書き作成 |

## 4. 生成した記事のチェック記録

プロンプトの品質を確かめるために生成した記事です（ai_only モード）。1 行目がタイトル、2 行目以降が本文の HTML です。

| ファイル | キーワード |
|---|---|
| `output-test1.txt` | 勤怠管理 エクセル 限界 |
| `output-test2.txt` | 有給休暇 管理 方法 |
| `output-test3.txt` | テレワーク 勤怠管理 課題 |
| `output-test4.txt` | 36協定 残業時間 上限（プロンプト修正前） |
| `output-test4b.txt` | 36協定 残業時間 上限（プロンプト修正後） |
| `output-test5.txt` | 勤怠管理システム 比較 選び方 |

5 本とも文字数・構成・キーワード・オリジナル性の条件を満たしていました。ただし 36協定の記事では【要確認】が 19 か所付き、考え方や助言の文にまで付いていました。そこで制約条件を「具体的な数字・期間・法律の条文や罰則・統計・公的機関の調査を述べた文にだけ付ける。付ける位置は句点の直前」に直したところ、11 か所に減り、すべて事実確認が必要な文になりました（`output-test4.txt` と `output-test4b.txt` を比べると分かります）。
